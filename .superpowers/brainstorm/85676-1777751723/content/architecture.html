Homepage Component Architecture

How V1 wireframe sections map to blocks and components

Page Structure

The homepage is a Page composed of 8 Blocks. Each block is a self-contained section component that uses existing shadcn components internally.

src/app/(frontend)/page.tsx → Homepage
// Page (single-route view of blocks)
HeroSection — featured project, headline, CTAs, social proof
Uses: Button, Badge
TrustStrip — 5 stat counters (10 years, 142+ projects, etc.)
Uses: Separator
PortfolioSection — filterable project grid with category pills
Uses: Button, Badge
ServicesSection — 3 service cards (Pergolas, Carports, Timber)
Uses: Card
ProcessSection — 4-step process (Call → Visit → Quote → Build)
Uses: Card
TestimonialsSection — 3 Google review cards
Uses: Card
ContactSection — quote form + map side by side
Uses: Card, Input, Label, Textarea, Button, Checkbox
FAQSection — 6-item accordion with sidebar text
Uses: Accordion

Key Decisions

Static content (hardcoded Czech copy)
All text from wireframe baked in. No props, no data fetching. Payload integration comes later.
Plain shadcn styles only
Use Card, Button, Badge, Input, Accordion as-is. Tailwind for layout (grid, flex, padding). No custom CSS.
Image placeholders
Gray boxes with labels (like the wireframe) instead of real images. Easy to swap later.
Server Components
All blocks are RSC by default. No client-side interactivity needed for wireframe stage.
